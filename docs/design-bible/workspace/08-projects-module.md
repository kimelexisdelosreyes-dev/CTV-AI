# 08 - Projects Module

## Purpose

Projects are the center of work. The Projects Module surfaces active context, not a generic project directory.

## Card Anatomy

- Project name.
- Type or template.
- Status.
- Progress.
- Team avatars or count.
- Current next action.
- Recent activity.
- AI activity.
- Due date or milestone.
- Primary action.

## Visual Treatment

Project cards should feel substantial and readable. Use progress and status sparingly. Avoid filling cards with metrics unless they explain the next action.

```text
+--------------------------------------------------+
| Fire Documentary                         Review  |
| Production | 72% complete | Due Friday           |
| Next: Review generated subtitles                 |
| AI: Subtitle generation completed 18 min ago      |
| Team: 6 members                                   |
| [Open project]                                    |
+--------------------------------------------------+
```

## Sorting

Default order:

1. Pinned projects.
2. Projects with pending user action.
3. Recently active projects.
4. Due soon.
5. Recently updated by team.

## Filtering

- Status.
- Owner.
- Team.
- Due date.
- Project type.
- Has pending AI review.
- Archived.

## States

- Pinned projects stay above default sorting.
- Archived projects are hidden by default.
- Empty state suggests project templates or assigned-work check.
- Completed projects appear only if review, export, or archive action remains.
