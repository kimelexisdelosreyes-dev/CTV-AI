# Python Ollama Adapter

Phase 4.7C.2B adds an isolated backend Ollama adapter. It wraps the existing `ollama_service.chat` transport rather than changing it. The production route remains `chat.py -> ai_router.py -> ollama_service.py`, and still uses `/api/chat`, non-streaming messages, existing prompt construction, configured timeout, and existing model roles.

Phase 4.7C.2C makes this adapter available through the default-off `CTV_ONE_AI_RUNTIME_ENABLED` runtime path; the legacy path remains default. See `021-backend-runtime-cutover.md`.

The adapter exposes configured CTV ONE model IDs, accepts only local synchronous Ollama requests, preserves model and a provider-neutral immutable message tuple exactly, invokes transport once, and normalizes text and provider-reported token counts. The tuple supports only `system`, `user`, and `assistant` roles; it is converted directly into Ollama's `{role, content}` messages with no sorting, merging, or prompt construction. Cancellation is checked before/after transport; the runtime also propagates cooperative cancellation by cancelling its adapter task. In-flight provider cancellation remains limited by the current `ollama_service.py` API, which accepts no cancellation token and provides no explicit upstream abort contract. Runtime retains retry, fallback, and timeout ownership. No live Ollama is needed for mock-based tests; cutover is feature-gated and default-off.
